# RAJAB FINANCE · архитектура MVP

Новый проект с нуля, 13.10.2026. Код предыдущих сайтов не используется. Локальная разработка; публикация, реальные платежи и приём реальных персональных данных запрещены до отдельного согласования.

## Слои
- Next.js App Router / TypeScript: публичный сайт, CRM, кабинет клиента, Node route handlers.
- Tailwind + локальные компоненты shadcn/ui: изумрудный #064E3B, зелёный #059669, золотой #C9A45C, фон #F8FAF9. Русский интерфейс, светлая/тёмная тема, sidebar/mobile navigation.
- Zod: входящие команды; Decimal.js: денежные значения в интерфейсе. В PostgreSQL суммы в копейках BIGINT; вычисления NUMERIC, без floating point.
- Supabase Auth SSR: серверная проверка пользователя; membership берётся из БД. Нет публичной регистрации организаций. Service role не используется для бизнес-команд сотрудников.
- PostgreSQL: RLS, составные FK (tenant_id,id), атомарные RPC, idempotency keys, append-only аудит. Проверки ролей внутри каждой мутации, RLS для чтения.
- Supabase Storage: приватный bucket, ограничения размеров/типов, серверный контроль magic bytes, выдача файла после проверки RLS.
- PDF-lib + встроенный кириллический шрифт на сервере. Только демонстрационные документы.
- Telegram outbox: транзакционная очередь; отправка серверным worker, минимальные данные, повторные попытки. В демо уведомления остаются в очереди.

## Локальный деморежим
PGlite (PostgreSQL WASM) запускает те же миграции/RPC/RLS, auth.uid() эмулируется только локально. Вымышленные пользователи/две организации. Подписанная HttpOnly сессия. DEMO_MODE нужно включить явно; на Vercel режим заблокирован. Данные на диске .demo, этот каталог никогда не коммитится. Деморежим не является заменой облачной интеграционной проверки Supabase Auth/Storage.

## Жизненный цикл
Заявка → предварительное согласование → ожидание закупки → приобретение + подтверждение собственности + файл закупки → окончательное согласование цены → договор со снимком условий → передача → поступления → закрытие. Заключить договор без закупки и окончательного согласования запрещено RPC. Подписанная цена/график/версия тарифа неизменяемы. Изменение условий не реализовано: нельзя тихо редактировать сделку.

## Права
Owner: операции организации/тарифы. Manager: клиенты, заявки, закупки, стандартные расчёты, договоры, передача. Cashier: ограниченные договоры, платежи, кассы. Client: только свои договоры, графики, поступления, PDF. Platform admin: только метаданные организаций/подписок, без автоматического доступа к клиентам. В MVP у пользователя одна организация; модель таблицы предусматривает явное расширение выбора активной организации.

## Денежный учёт
Цена = закупочная себестоимость + разовая согласованная прибыль. Тариф: фиксированный %, сетка по месяцам или индивидуальная прибыль (Owner). Первоначальный взнос — отдельная строка графика, его фактическое поступление фиксируется платёжной операцией, а не созданием договора. Оставшаяся сумма распределяется в копейках, последний платёж закрывает округление. Нет начисления на остаток/просрочку.
Платежи блокируют договор и кассу FOR UPDATE, защищены ключом операции, автоматически распределяются FIFO. Исправление — полная отмена исходного поступления с отдельной отрицательной записью и причиной, затем новая операция при необходимости. Кассовые переводы атомарны. Договорная прибыль отдельно от денег. Остаток = цена − сумма подтверждённых операций. Закупки и операционные расходы не вычитаются повторно из договорной прибыли.

## Границы
Нет банковского эквайринга, электронного подписания, юридически утверждённых условий, паспортов, публичного SaaS onboarding, биллинга подписок и CSV/XLSX. Документы закупки — пользовательское подтверждение, не автоматическая юридическая проверка. Перед живым запуском отдельные юридическая/шариатская экспертизы и восстановление из backup в staging.
