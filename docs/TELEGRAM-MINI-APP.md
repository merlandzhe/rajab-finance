# Telegram Mini App — RAJAB FINANCE

**Новый этап:** [кабинеты покупателя и предпринимателя](BUYER-PLATFORM.md) добавляет самостоятельную регистрацию, подтверждение контакта и адресную очередь уведомлений. Он ещё не опубликован. Описание ниже относится к прежней версии с приглашениями; её утверждения об отсутствии регистрации и старой настройке worker не относятся к новому исходному коду.

Добавлено в существующий проект на ветке `feature/client-portal`. Тестовое приложение опубликовано на https://rajab-finance-mini.vercel.app/mini. Одобренное Vercel-развёртывание `rajab-finance-demo.vercel.app` и FootballRamenskoe не обновлялись. Демобаза RAJAB обновлена по прямому разрешению пользователя. Реальные платежи не подключались.

15.10.2026 пользователь выбрал временный запуск Mini App на Vercel с возможностью последующего переноса. 16.10.2026 публикация выполнена через согласованный браузерный доступ. Актуальные цели, применённые миграции и оставшиеся проверки указаны в [журнале развёртывания](../deploy/README.md).

## Пользовательский путь

1. Владелец входит в существующую CRM по email и паролю. В настройках создаёт приглашение для своего кабинета. Для клиента — открывает его карточку и создаёт отдельное приглашение.
2. Владелец передаёт ссылку только соответствующему человеку после проверки личности. Ссылка даёт доступ к кабинету, действует 30 минут и используется один раз. Новая ссылка отменяет предыдущую; кнопка отмены удаляет неиспользованное приглашение.
3. Человек открывает ссылку в Telegram. `/mini` передаёт подписанные Telegram данные серверу. Сервер связывает числовой Telegram ID с конкретной существующей учётной записью.
4. Клиент попадает в `/cabinet`, владелец/сотрудник — в CRM, администратор платформы — в кабинет платформы. Следующие входы доступны через кнопку приложения в боте.
5. Клиент создаёт заявки и сообщает о платежах СБП/наличными через уже добавленный клиентский кабинет. Запись об оплате и уменьшение долга появляются только после подтверждения сотрудником. Mini App не списывает деньги.

Первый этап работает с **уже созданными Auth-аккаунтами**, связанными с профилем, активным участием в организации и карточкой клиента (`customers.auth_user_id`). Самостоятельной регистрации, автоматического создания аккаунтов, восстановления Telegram-привязки и переноса кабинета между Telegram-аккаунтами пока нет. Для неподготовленной карточки интерфейс сообщает о необходимости создать учётную запись. Имя, телефон и Telegram username не используются для поиска чужих договоров.

## Защита

- `TELEGRAM_MINI_APP_ENABLED=false` по умолчанию. Локальный деморежим и `DEMO_DEPLOYMENT=true` отключают Telegram API даже при включённом флаге.
- Проверяется HMAC-SHA256 по официальному алгоритму Telegram, дата не старше 5 минут, допустимое опережение часов 30 секунд, уникальность полей, числовой ID пользователя. `initDataUnsafe` не применяется.
- Только подписанный `start_param` может передать приглашение. Сервер не принимает из браузера роль, tenant, Auth UUID или Telegram ID.
- Таблицы привязок, хешей приглашений и повторов находятся в `private`, защищены RLS без прямых разрешений. `telegram_exchange` доступна только `service_role`, после проверки Telegram в API. Выпуск и отмена приглашений повторно проверяют права внутри SQL.
- Привязка, погашение приглашения и блокировка повтора выполняются одной транзакцией. Порядок query-параметров не позволяет обойти защиту от повтора. Неактивное членство блокирует новый вход. Просроченные записи повторов удаляются при обмене.
- Supabase Admin генерирует одноразовый hash для **проверенного существующего Auth UUID**, затем SSR-клиент обменивает его на обычную пользовательскую сессию. UUID проверяется до и после обмена. Ссылка/OTP, bot token и service role не возвращаются браузеру, письма не отправляются. Обычные операции продолжают использовать пользовательский JWT и прежние RLS.
- Все POST проверяют точный `APP_ORIGIN`. Ограничения запросов Telegram считаются по проверенному Telegram ID / пользователю CRM, без доверия к входящему `X-Forwarded-For`.
- Cookies HttpOnly и Secure в production; SameSite=None включается только для Mini App в production для Telegram Web. CSP разрешает встраивание только `https://web.telegram.org`, официальный SDK только с `https://telegram.org/js/telegram-web-app.js`. Без Mini App сохраняется запрет встраивания. Браузеры с запретом сторонних cookies могут требовать открытия в мобильном Telegram.
- Использование украденной ссылки до её погашения даёт доступ указанному кабинету: отправлять ссылки в общие чаты нельзя. В базе хранится только SHA-256 токена. Персональный код проходит через инфраструктуру Telegram в `startapp`.

## Подключение отдельного бота

Выбранный пользователем бот: [@RajabFinance_bot](https://t.me/RajabFinance_bot). Его публичное имя записано в настройках. Секрет с правильным именем сохранён пользователем в Vercel 16.10.2026; запущена пересборка. Настройка Main Mini App у бота и подлинность токена пока не проверены. HTTPS-адрес: https://rajab-finance-mini.vercel.app/mini.

Не использовать футбольный бот и не менять его токены, webhook или menu button.

1. Создать отдельного бота RAJAB FINANCE через официальный `@BotFather` (`/newbot`). Username публичный; токен вводится только в серверное хранилище секретов, не в чат, репозиторий или NEXT_PUBLIC-переменную.
2. Для испытаний используется отдельный HTTPS-адрес Mini App и по разрешению пользователя существующая демобаза RAJAB. Использовать только вымышленные данные. Подготовка к рабочему размещению в России и требованиям к персональным данным остаётся отдельным этапом; это изменение не подтверждает юридическую готовность.
3. Обе новые миграции уже применены к демобазе RAJAB `pqlhsxgtsubyereenysn`: `20261015141557_client_portal.sql`, затем `20261015144047_telegram_mini_app.sql`. Не повторять их и никогда не применять к Football `hfthtycwxwtmbncnjpum`.
4. Установить `DEMO_MODE=false`, `DEMO_DEPLOYMENT=false`, точный HTTPS `APP_ORIGIN`, реквизиты своего Supabase-совместимого Auth/DB и `SUPABASE_SERVICE_ROLE_KEY`. `ALLOW_REAL_INTAKE=false` оставить до отдельного решения о запуске.
5. Добавить `TELEGRAM_MINI_APP_BOT_USERNAME` (без @) и серверный `TELEGRAM_MINI_APP_BOT_TOKEN` именно нового RAJAB-бота. Перед включением проверить принадлежность токена через Bot API `getMe`, сравнить username. Сам токен и полный URL запроса не логировать.
6. Включить `TELEGRAM_MINI_APP_ENABLED=true` и **пересобрать** проект: CSP настраивается при сборке. Build/runtime должны использовать одинаковые значения флагов.
7. В BotFather настроить **Main Mini App** на `https://<отдельный-домен>/mini`, чтобы работали ссылки `https://t.me/<bot>?startapp=invite_<код>`. Menu Button: «Личный кабинет», тот же HTTPS URL. Одной настройки Menu Button без Main Mini App для приглашений недостаточно.
8. Создать первое приглашение владельцу через настройки CRM; затем — тестовому клиенту через карточку. Проверить с двух разных Telegram-аккаунтов на iPhone, что роли и договоры различаются.

Bot webhook для открытия Mini App не требуется. Настройка Main Mini App сама по себе не включает исходящие уведомления: существующий `/api/telegram` worker, отдельные `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `PUBLIC_TENANT_ID` и `CRON_SECRET` подключаются отдельно. Рассылка клиентам/по нескольким организациям в этом изменении не реализована. Пользователю не отправляются сообщения автоматически.

## Проверки и ограничения

Локальные тесты охватывают подпись, подмену ID/бота, дубликаты параметров, срок входа, повтор, приглашения чужой организации, недостаточные роли, истечение/отмену/переиздание, неактивного владельца/клиента и несовпадение Auth UUID при выдаче сессии. SQL выполняется в PostgreSQL-совместимом PGlite с теми же миграциями и RLS; Auth SDK в тесте обмена заменён контролируемым двойником.

Результат 15.10.2026: 40 тестов проходят, production-сборки с выключенным и включённым Mini App успешны, 56 HTTP-проверок существующих функций и 9 проверок включённого Mini App проходят. Повторная сборка потребовала исключить повреждённый кеш Turbopack; исходный кеш сохранён вне проекта. Браузерную проверку локально выполнить не удалось: установленный Playwright не содержит Chromium, загрузка браузера вернула повреждённый архив. Отображение и работу официального SDK на iPhone необходимо проверить после подключения. Этот результат не является подтверждением живого входа через Telegram.

Для воспроизведения: `npm test`; обычная сборка и `npm run check:http`; затем `TELEGRAM_MINI_APP_ENABLED=true DEMO_MODE=false npm run build` и `npm run check:telegram-http`. Последняя команда сама поднимает временный локальный сервер с синтетическим токеном, проверяет защитные заголовки, отказы неподписанному входу/чужому Origin и закрывает сервер. Живая БД не используется.

Перед живым запуском остаются обязательными проверки настоящего Supabase Auth и Telegram: вход/выход/новый вход на iPhone, сохранение cookies, переходы назад, загрузка документов, приватность кабинетов двух клиентов, постановка заявки и подтверждение платежа владельцем. Настоящая связка не проверялась без бота и отдельного сервера. После неудачного обмена уже погашенных initData требуется закрыть Mini App и открыть заново.

Отмена приглашения не отключает уже привязанный Telegram и не отзывает существующие Auth-сессии. Потеря Telegram-аккаунта требует отдельной процедуры восстановления с проверкой личности и отзывом сессий. Не выдавать новый доступ без такой проверки.

Официальные источники: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Supabase generateLink](https://supabase.com/docs/reference/javascript/auth-admin-generatelink), [Supabase verifyOtp](https://supabase.com/docs/reference/javascript/auth-verifyotp).
