# HESAP: переход на @Hesap95bot

## Текущий статус

- Новый Telegram-бот: `@Hesap95bot`.
- Тестовая ветка HESAP использует это имя в настройках примеров и CI.
- Preview-переменная `TELEGRAM_MINI_APP_BOT_USERNAME` обновлена для рабочей ветки.
- **Production не переключён**: в нём всё ещё используется токен старого бота. Не обновлять только username без токена: проверка `getMe` и проверка подписанного `initData` должны использовать один и тот же новый бот.
- Vercel-проект `rajab-finance-mini`, Supabase и существующие договоры не создавать заново и не удалять.

## Настройка BotFather

1. В `@BotFather` открыть `/mybots` → `@Hesap95bot`.
2. Установить отображаемое имя `HESAP | Рассрочка`, описание и аватар.
3. `Bot Settings` → `Configure Mini App` → `Enable Mini App`; адрес `https://rajab-finance-mini.vercel.app/mini`.
4. `Bot Settings` → `Menu Button` (или `/setmenubutton`): текст `Открыть HESAP`, тот же адрес.
5. Не публиковать ссылку `https://t.me/Hesap95bot?startapp` как рабочую до переключения токена.

## Переключение Production после сверки интерфейсов и авторизации

1. Через **Vercel → rajab-finance-mini → Settings → Environment Variables → Production** безопасно заменить `TELEGRAM_MINI_APP_BOT_TOKEN` на токен нового бота. Никогда не отправлять токен в чат или GitHub.
2. В той же среде заменить `TELEGRAM_MINI_APP_BOT_USERNAME` на `Hesap95bot`. `APP_ORIGIN` остаётся `https://rajab-finance-mini.vercel.app` (если совпадает с фактическим Production-адресом).
3. Для нового бота желательно обновить серверный `TELEGRAM_WEBHOOK_SECRET` на отдельное случайное значение длиной 32–256 символов. Безопасно выполнять переключение вместе с релизом.
4. Сначала оставить `TELEGRAM_NOTIFICATIONS_ENABLED=false`, пока новый бот не будет запущен получателями. Это защищает очередь от массовых ошибок доставки.
5. Выпустить проверенную production-сборку **только после сохранения последних изменений кабинетов**. Настроить новый webhook на `https://rajab-finance-mini.vercel.app/api/telegram/webhook`, убедившись через `getMe` в имени `Hesap95bot`, затем проверить `getWebhookInfo`.
6. Проверить на отдельных тестовых Telegram-аккаунтах вход покупателя, предпринимателя и владельца, подтверждение телефона, заявки и уведомления. Старую Supabase не сбрасывать.
7. Попросить пользователей открыть `@Hesap95bot`, нажать `Start`, открыть Mini App. Telegram ID остаётся прежним, но новый бот **не может первым написать пользователю**, пока тот его не запустил.
8. Включать реальные уведомления после успешного теста доставки и проверок очереди. Старого бота отключать последним, после миграции ссылок и пользователей.

## Технические замечания

- У нового бота собственный токен подписи `initData`; использование токена старого бота будет отклонено при авторизации.
- Существующие записи клиентов в Supabase связаны с Telegram ID, а не с username бота; база может быть сохранена. Реальная повторная авторизация всё равно должна пройти тесты.
- Старые чаты Telegram в новый бот не переносятся автоматически.
- Этот документ **не разрешает** без дополнительной проверки перезаписывать Production: сначала выполнить `docs/RELEASE-GATE.md`.
