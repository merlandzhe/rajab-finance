## Отдельное тестовое развёртывание

Проверка после сохранения токена: `dpl_FSpZzB4WboaudQJvmBEcabMansq3` — READY, сборка 1м 2с, домен Mini App назначен. `GET /api/state` без сессии возвращает 401; POST `/api/auth/telegram` с правильным Origin и поддельными initData возвращает 401 с ошибкой проверки Telegram (не 503 отсутствующего токена). Это проверяет отказ неподписанному запросу, но не подтверждает принадлежность токена или успешную авторизацию.

Фактическая цель — существующий проект `rajab-finance-mini` в команде `merlan`. Не создавать его повторно. Используется та же кодовая база.

Не обновлять и не переносить домен одобренного `rajab-finance-demo.vercel.app`. Не трогать проект FootballRamenskoe, его БД, бота, переменные и домены.

1. Подготовить чистую копию отслеживаемых git-файлов текущего коммита. Не включать локальные секреты, `.demo`, `.next`, `node_modules`, `.git`, `.vercel` и `supabase/.temp`.
2. **Только в копии для загрузки** заменить корневой `vercel.json` содержимым `deploy/vercel-mini.json`. Исходный `vercel.json` сохраняет закрытый режим одобренного демо: в нём зафиксирован `DEMO_DEPLOYMENT=true`, который отключает Mini App. Загружать исходный конфиг в Mini App нельзя.
3. В выбранном Vercel-окружении установить значения из `deploy/mini.env.example`. Несекретные флаги должны совпадать при сборке и во время работы; конфиг намеренно не переопределяет их через legacy-поле `env`. `APP_ORIGIN` — точный HTTPS origin будущего адреса, без пути `/mini`. Токен и service role вводить как серверные секреты. Не присылать их в чат.
4. Для текущего теста по разрешению пользователя используется демобаза RAJAB `pqlhsxgtsubyereenysn`. Новые миграции уже установлены — не запускать повторно. Не применять миграции к Football. Не включать платную ветку/план без согласования стоимости. Только вымышленные клиенты; подготовка рабочего хранения российских персональных данных остаётся отдельным этапом.
5. Собрать и развернуть код, дождаться `READY`. Проверить `/mini`, отказ неподписанному входу, отсутствие публичного доступа к CRM и данным. `public:false` скрывает исходники и логи Vercel; доступ к данным обеспечивает авторизация приложения. Этот флаг сам по себе не защищает сайт паролем.
6. Проверить, что Deployment Protection выбранного окружения не мешает входу через Telegram WebView. Не отключать защиту одобренного демо. При ограничении Vercel менять настройки только выбранного тестового окружения и только сохраняя защиту данных приложением.
7. После проверки токена нового RAJAB-бота через `getMe` настроить Main Mini App и Menu Button на `https://<проверенный-адрес>/mini`. До публикации не указывать в боте выдуманный адрес.
8. Через обычный вход владельца создать персональное приглашение. Проверить на iPhone вход клиента/владельца, изоляцию договоров, новую заявку и подтверждение тестовой оплаты. Результаты сохранить в `docs/TELEGRAM-MINI-APP.md`.

## Последующий перенос

Next.js поддерживает запуск на собственном Node.js-сервере или в контейнере. При переносе настроить HTTPS, серверные секреты, `APP_ORIGIN`, Auth/Storage URL, обработку загрузок и фоновых уведомлений; обновить адрес Main Mini App и Menu Button в том же боте. Сам Telegram username менять не требуется. Перенос БД и учётных записей планируется отдельно от переноса веб-приложения.

Источники: https://vercel.com/docs/project-configuration ; https://nextjs.org/docs/app/guides/self-hosting ; https://core.telegram.org/bots/webapps .
